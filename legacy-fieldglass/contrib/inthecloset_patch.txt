# APDIF `-intC` hidden menu patch (Cobra/pflag version)

## Why this shape

If APDIF uses Cobra/pflag, a single-dash multi-letter token like `-intC` is **not** parsed as a normal long flag.
pflag treats single-dash input as shorthand letters, not a long option. So the robust implementation is:

1. Add a tiny argv rewrite in `main.go`
2. Register a hidden command named `intheCloset`
3. Keep it out of normal `-h` / `--help` output
4. Let `apdif -intC` and `apdif --intC` both route into that hidden command

---

## 1) Patch `main.go`

Replace your current `main.go` with this shape, or merge the `normalizeHiddenAliases` call into your existing startup path.

```go
package main

import (
	"os"
	"strings"

	"apdif/cmd"
)

func normalizeHiddenAliases(argv []string) []string {
	if len(argv) <= 1 {
		return argv
	}

	out := make([]string, 0, len(argv))
	out = append(out, argv[0])

	for _, a := range argv[1:] {
		switch strings.TrimSpace(a) {
		case "-intC", "--intC":
			out = append(out, "intheCloset")
		default:
			out = append(out, a)
		}
	}

	return out
}

func main() {
	os.Args = normalizeHiddenAliases(os.Args)
	cmd.Execute()
}
```

- `./apdif -intC` prints the hidden cheat block
- `./apdif --intC` prints the hidden cheat block
- `./apdif intheCloset` also works
- `./apdif -h` does **not** show `intheCloset`

## 5) Notes

- If APDIF is already using Cobra/pflag, this is the correct shape for `-intC`.
- Do **not** try to register `-intC` as a normal Cobra flag; pflag interprets single-dash multi-letter input as shorthand bundling, not a long flag.
- `Hidden: true` keeps the command out of normal help output.
- The argv rewrite keeps your desired operator UX without polluting the normal command surface.
